# 用自动控制原理看懂 C1 电机控制

适合第一次读这个工程的队友。先把系统当成“左右各一套定速巡航”：上位机给目标轮速，编码器测真实轮速，STM32 根据差值调整电机 PWM。

## 1. 先看控制框图

```text
上位机目标轮速
      │
      ▼
加速度斜坡 → 目标速度 → (目标 - 实测) → PI 控制器 → PWM → BTS7960 → 电机/车轮
                                ▲                              │
                                └──────── 编码器测速 ──────────┘
```

- **目标速度**：希望车轮达到的速度，例如 200 mm/s。
- **实测速度**：编码器计数换算出来的速度。
- **误差**：目标减实测。目标 200、实测 150，误差为 +50 mm/s。
- **PI 控制器**：把速度误差变成 PWM 命令。PWM 越大通常电机越快，但负载和电池电压也会影响结果。
- **反馈**：编码器不断测量车轮，控制器下一周期再用新的实测速度修正 PWM，这就是闭环。

树莓派 ROS2 将车体前进速度 `v` 和转向速度 `ω` 转成左右轮速度：

```text
左轮 vL = v - ω × L / 2
右轮 vR = v + ω × L / 2
```

`L` 是左右轮中心距（本项目设计值 428 mm）；STM32 不负责导航，只负责分别跟踪 `vL`、`vR`。

## 2. 代码里的 PI 做什么

每次控制更新都执行：

```text
误差 e = 斜坡后的目标速度 - 编码器测得速度
积分 I = 上次积分 + Ki × e × 实际采样秒数
PWM = 限幅(Kp × e + I)
```

- **P** 根据当前误差立即增加/减少 PWM。P 太小反应慢，太大容易来回振荡。
- **I** 累积长期存在的误差，用于弥补摩擦、负载变化等造成的偏差。I 太大会过冲。
- **积分限幅和抗饱和** 防止 PWM 已经到顶时积分继续无限变大。
- PWM 输出范围为 `-1000..1000`，正负号表示两个方向，1000 表示 100% 占空比。

这些参数在 `C1_Keil/Core/Inc/config.h`：

```c
#define SPEED_PI_KP             0.30f
#define SPEED_PI_KI_PER_SECOND  2.0f
```

它们只是第一次上电的起始值，没有经过本车实测整定。不要在未确认编码器比例前调 PI，否则比例错误会让反馈和控制同时失真。

## 3. 速度斜坡和软停

PI 负责“当前目标怎么追上”；斜坡负责“目标本身不要突然跳变”。速度每个周期最多变化：

```text
允许变化 = 最大加速度 × 实际周期
```

本项目默认加速度为 300 mm/s²，目标速度控制周期为 20 ms。比如从 0 加到 200 mm/s，不会一步跳到 200，而是逐步增加目标。

`CMD_STOP` 把左右轮目标设为 0，进入 `STOPPING`；PI 继续工作，轮速降到门槛后进入 `IDLE`。反向命令也会先经过斜坡，目标经过 0 后再往反方向走。

## 4. 编码器怎么算速度和里程

设轮径 `D`、车轮转一圈计数 `N轮`、本次采样增量 `ΔN`、采样时间 `Ts` 秒：

```text
每计数距离 = π × D / N轮
速度(mm/s) = ΔN × 每计数距离 / Ts
里程(mm)   = 累计计数 × 每计数距离
```

程序从 TIM2 读取左轮，从 TIM8 读取右轮；两侧速度和里程由同一个 Control 任务更新。换算使用 `config.h` 里的轮径与 `ENCODER_COUNTS_PER_WHEEL_REV`。

### 为什么编码器计数必须实测

用户给的编码器截图写着“16 PPR”和 AB 相差 90°，但没有说每转是电机轴一圈还是减速箱输出轴一圈。代码先采用这个**待校准假设**：

```text
16 PPR × A/B 四倍频 × 56 减速比 = 3584 计数/车轮一圈
```

如果 16 PPR 已经是减速箱输出轴的值，那就不是 3584。不要靠猜：断开电机动力，准确转动车轮一圈，读取定时器计数差；左右轮各测一次。把实测结果填进 `ENCODER_COUNTS_PER_WHEEL_REV`。向前转时，两侧编码器速度都应为正；必要时把对应 `ENCODER_*_SIGN` 改成 `-1`。

## 5. 任务怎样分工

源码集中在 `C1_Keil/Core`，Keil 与 GCC 共用它。主逻辑只有两个任务：

| 部分 | 用简单的话说 |
| --- | --- |
| USART3 接收中断 | 每次拿一个字节；完整 CRC 正确的帧才入队。 |
| TIM7 中断 | 每毫秒通知控制任务。 |
| `Task_Control` | 顺序处理命令、安全超时、编码器、速度斜坡、PI 和 PWM。速度控制至少每 20 ms 做一次。 |
| `Task_Telemetry` | 从发送队列取状态或 ACK 并发到串口；它是唯一发送者。 |

把控制放在一个任务里，是为了让“命令、编码器反馈、PI 和 PWM”依次更新，避免多个任务同时修改目标速度或占空比。读 `app_tasks.c` 时可以先找 `handle_command()`、`run_speed_control()`、`update_communication_safety()` 三个函数。

## 6. 状态和真实保护边界

| 状态 | 含义 |
| --- | --- |
| `IDLE` | PWM 清零，软件输出关闭 |
| `RUN` | 跟踪左右轮目标速度 |
| `STOPPING` | 速度目标斜坡减到 0 |
| `FAULT` | PWM 清零并锁定，满足低速条件后才可清除 |

500 ms 没有合法串口帧且车辆正在运行时，进入软停；1 s 仍未恢复则锁定。`CMD_ESTOP` 是软件急停，只能让正常运行的固件清 PWM、禁止输出；真正能在 MCU 卡死时停电机的急停必须来自独立硬件电路。

当前还没有接入电池电压或电机电流 ADC。状态帧电压字段 `0xFFFF` 表示未知，代码不做基于估算值的过流/欠压保护。编码器堵转检测默认关闭，等每轮计数标定后再考虑开启。

## 7. 开发板和驱动板的引脚复用

开发板原理图显示了一些复用冲突，上车前需按真实接线逐项检查：

| 信号 | 当前固件 | 板上复用/注意事项 |
| --- | --- | --- |
| USART3 | PB10、PB11 | P7 USART3 TTL 接口 |
| 电机 PWM | PB4、PB5、PB0、PB1（TIM3） | PB4/PB5 接 W25Q128；PB0/PB1 与触摸屏相关信号复用；使用 PWM 时相应板载功能不能同时用。固件把 Flash 片选 PG8 拉高。 |
| 左编码器 | PA15、PB3（TIM2） | 也可作 JTAG；调试使用 SWD。 |
| 右编码器 | PC6、PC7（TIM8） | 也可作 USART6，不能同时占用。 |
| BTS7960 EN | 默认不用 MCU 控制 | 按模块资料把 EN 拉高；PA5/PF11 与触摸屏复用。只有确认接线后才将 `MOTOR_USE_EN_PINS` 设为 1。 |
| 外部电源开关 | 默认关闭 | PA0 是 UART4_TX 引出，不是板载电机开关；只有接入经过确认的外部电路后才能启用 `MOTOR_USE_POWER_SWITCH`。 |

BTS7960 的逻辑 VCC 5 V、电机电源和 STM32 共地关系要按手头模块接线图核对。模块标注的 `IS` 电流检测脚只有在确认输出电路、接入 ADC 并标定后，才能用于真实电流保护。

## 8. 建议的上车顺序

1. 断开电机动力，只接控制板和串口，确认能读到状态帧。
2. 手动转左右轮各一整圈，确认计数比例和速度方向；修正 `ENCODER_COUNTS_PER_WHEEL_REV` 与方向符号。
3. 轮子架空，逐个电机给很低的速度命令，检查电机方向、编码器方向和 PWM 引脚。
4. 先单轮调整 `Kp`，让速度能稳定跟随；再逐渐增加 `Ki` 消除稳态误差。记录目标速度、实测速度和占空比。
5. 双轮联调后，再接入经实测的电流/电压检测和独立硬件急停。

每一步先确认当前因果关系，再往下一步走。这里的代码尚未在目标开发板和机器人上实测，编译成功也不能证明接线、轮向和编码器比例正确。

`tools/sim_logic.py` 可以用来观察斜坡和 PI 的大致变化，但它的一阶电机模型不是实际电机参数，也不等同于固件测试，不能用它证明稳定性或安全性。

## 9. 推荐阅读顺序

1. `.agent/项目导览.md`：了解仓库边界和文件位置。
2. `C1_Keil/Core/Inc/config.h`：先认识机械参数、方向和控制参数。
3. `C1_Keil/Core/Src/app_tasks.c`：看一条命令如何进入状态机和速度 PI。
4. `encoder.c`：看计数如何换算成速度和里程。
5. `motor.c`：看控制器输出怎样变成 RPWM/LPWM。
6. `protocol.c` 和 `main.c`：最后看串口帧、外设启动和中断。
