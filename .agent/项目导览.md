# C1 STM32 控制板项目导览

面向第一次读这个仓库的队友。先把它理解为机器人的“左右轮速度执行器”：树莓派负责 ROS2 导航和决策，STM32 收到左右轮目标速度后，独立测量两侧轮速、控制电机并回报状态。

想按命令流完整看懂方案、代码和上板步骤，请读 [方案与代码逐步讲解](方案与代码逐步讲解.md)；控制原理入门见 [自动控制入门与改造指南](自动控制入门与改造指南.md)。当前协议字段见 [`docs/02_上下位机通信协议.md`](../docs/02_上下位机通信协议.md)。

## 1. 系统做什么

```text
树莓派 ROS2
    │ 左右轮速度命令（USART3）
    ▼
STM32F407 → BTS7960 → 左右电机 → 车轮
    ▲                              │
    └──────── 编码器测速 ──────────┘
    │ 状态、轮速和里程（USART3）
    └──────────────────────> 树莓派
```

本仓库是下位机固件，不包含 ROS2 导航、建图、路径规划和完整传感器融合。两套工程共用 `C1_Keil/Core` 源码：Keil 工程在 `C1_Keil/Project`，命令行 GCC 工程在 `C1_GCC`。

## 2. 一条速度命令如何变成车轮转动

1. 树莓派通过 USART3 发送左右轮速度，例如 `200 mm/s、200 mm/s`。
2. USART3 中断逐字节解析帧；长度和 CRC 正确后，把完整命令放进接收队列。
3. `Task_Control` 取命令、做速度限幅，并让目标速度按加速度限制逐渐变化。
4. 同一个任务每 20 ms 读取 TIM2/TIM8 编码器，计算左右轮速度。
5. PI 控制器比较目标速度和实测速度，算出左右轮 PWM。
6. `motor.c` 把 PWM 正负号转换为 BTS7960 的 RPWM 或 LPWM 输出。
7. `Task_Telemetry` 是唯一的 UART 发送者，每 50 ms 发一次速度、里程和状态。

## 3. 任务和中断

| 名称 | 作用 | 频率/触发 |
| --- | --- | --- |
| USART3 接收回调 | 逐字节解析；只把完整帧放进队列 | 每个收到的字节 |
| TIM7 中断 | 计毫秒并通知控制任务 | 1 kHz |
| `Task_Control` | 命令、安全判断、编码器、速度斜坡、PI、看门狗 | 每个 TIM7 通知；速度环至少每 20 ms 一次 |
| `Task_Telemetry` | 发送状态帧和 ACK | 等待发送队列 |

两个任务是有意减少后的结构：命令、目标、反馈和 PWM 都由一个控制任务顺序修改，减少多任务同时改电机状态的困难。当前没有传感器采样任务。

## 5. 状态怎么理解

- `IDLE`：不输出 PWM，等待命令。
- `RUN`：控制左右轮跟踪目标速度。
- `STOPPING`：目标斜坡降为零；轮速足够低后回到 IDLE。
- `FAULT`：PWM 清零并锁定；轮子停稳后用 `CMD_CLEAR_ESTOP` 清除。

500 ms 没有合法串口帧且车辆正在动时，固件进入软停；1 s 仍未恢复则锁定。`CMD_ESTOP` 是软件急停，不能替代硬件切断电机动力的急停按钮。

## 6. 上车前需要改/确认的参数

1. **编码器每轮计数**：资料给出 16 PPR，但没有写清每转对应电机轴还是减速箱输出轴。代码暂按 `16 × 4 × 56 = 3584` 个计数/轮转；手动将每个车轮转一整圈，实测计数后更新 `ENCODER_COUNTS_PER_WHEEL_REV`。
2. **方向**：机器人向前时左右速度都应为正。编码器方向用 `ENCODER_LEFT_SIGN`、`ENCODER_RIGHT_SIGN` 修正，电机方向用 `MOTOR_LEFT_SIGN`、`MOTOR_RIGHT_SIGN` 修正。
3. **引脚复用**：PWM PB4/PB5/PB0/PB1 和开发板 Flash/触摸屏有冲突；左编码器 PA15/PB3 与 JTAG 复用；PC6/PC7 同时是 USART6；PA5/PF11 与触摸屏复用。具体见控制原理指南和原理图。
4. **电压/电流保护**：当前未接入 ADC，状态帧的电压 `0xFFFF` 表示未知；占空比估算不作为真实电流保护。堵转判断默认关闭。
5. **急停**：`0x03` 只在软件层清零 PWM 和锁定输出。需要外部硬件急停/断电链路才能在 MCU 故障时仍可靠切断电机。

PI 参数 `SPEED_PI_KP`、`SPEED_PI_KI_PER_SECOND` 是起始值，必须先校准编码器并架空低速调试后再整定。

## 7. 阅读顺序

先读本导览，再按 `config.h → app_tasks.c → encoder.c → motor.c → protocol.c → main.c` 顺序读。这样可以先看“给定和反馈怎么进控制器”，再看电机输出和底层中断。

联调时可使用 `tools/serial_tester.py`：先监听状态，再发低速命令，确认电机方向、编码器符号和速度比例。当前源码尚未针对实际接线和编码器参数完成上车验证。
