# C1 固件架构与任务划分

平台：STM32F407ZGT6 + FreeRTOS（CubeMX 生成，HAL 库）
对应任务书第 1 条：FreeRTOS 任务划分、优先级与调度策略；第 3 条：电机驱动层。

## 一、总体结构

采用「中断采集 + 任务处理」的两层结构：

- **中断层**只做最轻的事：串口按字节收进环形缓冲、IDLE 中断标记一帧结束、1kHz 定时器给出控制节拍。中断里不做浮点运算、不发队列的阻塞调用。
- **任务层**做全部逻辑：解析帧、算速度、跑控制环、更新 PWM、监控安全。
- 任务之间只用队列（Queue）和二进制信号量通信；共享的电机状态用临界区或原子读写保护。

## 二、任务表

| 任务 | 优先级 | 周期 / 触发 | 栈 | 职责 |
| --- | --- | --- | --- | --- |
| `Task_Safety` | 5（最高） | 1kHz 节拍 + 事件 | 256 words | 安全监控：通信超时、堵转、过流估算、急停状态机；直接关断 PWM |
| `Task_Motor` | 4 | 1kHz | 384 words | 速度环 PI、斜坡限幅、PWM 占空比更新、方向控制 |
| `Task_Encoder` | 3 | 100Hz | 256 words | 读 TIM2 / TIM8 计数、计算转速与累计里程、消抖与滤波 |
| `Task_Comm` | 3 | 事件（帧到达） | 512 words | 串口帧解析、命令执行、周期上报（20Hz） |
| `Task_Sensor` | 2 | 100Hz | 256 words | 传感器采样（电池电压、预留 IMU/环境传感器接口） |
| `Task_Monitor` | 1（最低） | 1Hz | 256 words | 喂独立看门狗、统计运行时间、记录故障码 |
| `Task_Idle` | 0 | - | - | FreeRTOS 空闲任务，负责回收被删除任务的栈 |

调度策略：抢占式调度（`configUSE_PREEMPTION=1`），同级任务时间片轮转。1ms 的 SysTick 作为时基，控制环用定时器任务通知（`vTaskNotifyGiveFromISR`）唤醒，避免忙等。

优先级设计原则：安全 > 控制 > 通信 = 采集 > 传感器 > 维护。安全任务永远最高，保证任何情况下都能在 1ms 内关断 PWM。

## 三、中断分配

| 中断 | 优先级 | 用途 |
| --- | --- | --- |
| `USART3_IRQn` | 5 | 接收字节入环形缓冲；IDLE 中断标记帧尾，释放信号量给 `Task_Comm` |
| `TIM7_IRQn` | 6 | 1kHz 控制节拍，任务通知唤醒 `Task_Safety` 与 `Task_Motor` |
| `TIM5`（编码器模式） | 不产生中断 | 硬件四倍频计数，任务轮询读取 |
| `SysTick` | 15 | FreeRTOS 时基 |

说明：USART3 采用 DMA + IDLE 空闲中断收不定长帧；发送用 DMA，避免阻塞任务。

## 四、电机驱动层

### 4.1 BTS7960 真值表

| RPWM | LPWM | 结果 |
| --- | --- | --- |
| PWM | 0 | 正转，调速 |
| 0 | PWM | 反转，调速 |
| 0 | 0 | 自由停车（滑行） |
| 1 | 1 | 刹车（能耗制动） |

实现要点：

- 用 TIM3 的四个通道分别产生两路电机的 RPWM / LPWM，PWM 频率取 20kHz（超出人耳听域，也远离 BTS7960 的开关损耗拐点）。
- TIM3 的 ARR 固定，占空比用比较寄存器实时更新；两路电机共用同一频率。
- 换向时先降速到阈值以下再反向，避免反接制动电流冲击电池（12Ah/10A 的 BMS 很敏感）。
- 急停实现：RPWM=LPWM=1 立即刹车，同时拉低 EN（如接）使输出级关断；随后进入锁定状态，需收到「清除急停」命令才恢复。

### 4.2 速度环

- 控制周期 1ms，速度环 200Hz（每 5ms 计算一次）即可。
- 采用增量式 PI：`u += Kp*(e-e_1) + Ki*e`，输出限幅 ±100%。
- 前级加斜坡限幅：目标速度按最大加速度（默认 0.5 m/s²）逐步逼近，实现软启动，抑制启动电流冲击。
- 死区补偿：占空比绝对值低于 8% 时电机不转，直接输出 0，避免堵转发热。

## 五、编码器测速与里程计

- TIM2 / TIM8 配置为编码器模式（TI12：A、B 双相四倍频），计数器自动加减。
- 每 10ms 读取一次计数增量：`delta = (int16)(cnt_now - cnt_last)`。
- 转速换算：`n_rps = delta / 2464 * 100`（2464 = 11 线 ×4 × 1:56）。
- 线速度：`v = n_rps * π * 0.1`（m/s）。
- 里程累计：`odo_mm += delta * 314.2 / 2464`，单位 mm，用 int32 保存。
- 所有系数集中在 `config.h` 的宏里（`ENC_PPR`、`GEAR_RATIO`、`WHEEL_DIA_MM`），标定后只改这一处。

## 六、安全监控（对应任务书"安全监控"任务）

| 故障 | 判据 | 处置 |
| --- | --- | --- |
| 通信丢失 | 500ms 未收到任何合法帧 | 软停（斜坡降到 0） |
| 通信丢失升级 | 1s 未恢复 | 急停锁定 |
| 堵转 | 占空比 > 30% 且 500ms 内编码器无计数 | 停机该轮并报故障码 |
| 过流（估算） | 母线总电流估算超 8A（电池 10A 上限，留余量） | 限幅降速，持续 2s 未恢复则急停 |
| 电池欠压 | 电压 < 10.5V | 告警；< 10V 停机 |
| 程序跑飞 | 独立看门狗 IWDG（1s） | 复位 |

状态机：`INIT → IDLE → RUN → FAULT`，FAULT 又分 `FAULT_COMM`、`FAULT_STALL`、`FAULT_ESTOP`、`FAULT_UVLO`，故障码随状态帧上报给树莓派，便于 C3 侧决策。

## 七、电流约束说明（重要）

电池持续放电只有 10A，而单个 JGB37-555 的堵转电流可达 8～12A。因此必须：

1. 启动和换向一律走斜坡，禁止阶跃给定；
2. 总电流估算（PWM 占空比 × 额定电流 + 堵转检测）超过 8A 即限幅；
3. 两轮同时堵转时优先降速而不是加大占空比；
4. 上位机（C3）下发速度前也应做梯形速度规划，避免急停急起。
