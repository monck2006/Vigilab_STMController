# C1 上下位机通信协议

适用范围：树莓派（上位机，ROS2）↔ STM32F407（下位机，运动控制）
物理层：USART3，PB10=TX、PB11=RX，TTL 3.3V，共地；默认 115200 8N1，可升到 460800。

## 一、帧格式

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 SOF | 2 B | 固定 `0xAA 0x55` |
| 长度 LEN | 1 B | `SEQ + CMD + DATA` 的总字节数（不含帧头、LEN 自身和 CRC） |
| 序号 SEQ | 1 B | 0～255 循环，用于丢帧检测 |
| 命令 CMD | 1 B | 见命令表 |
| 数据 DATA | N B | 按命令定义，**小端序（Little-Endian）** |
| 校验 CRC | 2 B | CRC16-Modbus（多项式 0xA001，初值 0xFFFF），覆盖 LEN～DATA，小端存放 |

收帧流程：等待 `0xAA 0x55` → 读 LEN → 收齐 LEN 字节 → 收 2 字节 CRC → 校验通过才交给命令分发。CRC 错误或超时（帧间 10ms）即丢弃，并计数。

## 二、数据字段约定

| 类型 | 长度 | 单位 | 说明 |
| --- | --- | --- | --- |
| `i16` | 2 B | mm/s | 线速度，有符号；负值表示倒退 |
| `u16` | 2 B | mm | 里程/距离 |
| `i32` | 4 B | mm | 累计里程 |
| `u16` | 2 B | mV | 电压 |
| `u8` | 1 B | - | 状态位、故障码 |

## 三、命令表

### 上位机 → 下位机

| CMD | 名称 | DATA | 说明 |
| --- | --- | --- | --- |
| `0x01` | 设置轮速 | `i16 v_left, i16 v_right` | 左右轮线速度，mm/s；下位机内部做加速度限制 |
| `0x02` | 软停 | 无 | 按斜坡减速到 0，保持使能 |
| `0x03` | 急停 | 无 | 立即刹车并锁定，需 `0x04` 解除 |
| `0x04` | 清除急停 | 无 | 仅在停止状态下有效 |
| `0x05` | 复位里程计 | 无 | 左右累计里程清零 |
| `0x06` | 设置 PID | `i16 kp_x1000, i16 ki_x1000` | 可选，调试用；掉电不保存 |
| `0x07` | 心跳 | 无 | 上位机 10Hz 发送，也可用 `0x01` 代替 |

### 下位机 → 上位机

| CMD | 名称 | DATA | 说明 |
| --- | --- | --- | --- |
| `0x10` | 状态上报 | `u8 state, u8 fault, u16 vbus_mV, i16 v_left, i16 v_right, i32 odo_left, i32 odo_right, u8 flags` | 周期 20Hz 主动上报 |
| `0x11` | 单次应答 | 同 `0x10` | 收到上位机查询后立即回一帧 |
| `0x7F` | ACK / NACK | `u8 ack_cmd, u8 code` | `code=0` 成功，非 0 为错误码 |

## 四、状态与故障码

`state`：`0x00` INIT，`0x01` IDLE，`0x02` RUN，`0x03` FAULT。

`flags`：

| 位 | 含义 |
| --- | --- |
| bit0 | 驱动电源已合闸（急停断电方案里断开时为 0） |
| bit1 | 输出级已使能 |
| bit2 | 急停锁定中（需发 `0x04` 清除） |
| bit3~7 | 保留，置 0 |

`fault`：

| 值 | 含义 |
| --- | --- |
| `0x00` | 正常 |
| `0x01` | 通信超时停车 |
| `0x02` | 急停锁定 |
| `0x03` | 堵转 |
| `0x04` | 过流限幅中 |
| `0x05` | 电池欠压 |
| `0x06` | 编码器异常（长时间无计数但占空比很高） |

## 五、超时与安全联动

| 条件 | 下位机动作 |
| --- | --- |
| 500 ms 未收到合法帧 | 软停，`fault=0x01`，保持可恢复 |
| 1 s 仍未收到 | 进入急停锁定，`state=FAULT` |
| 收到 `0x03` 急停 | 立即刹车锁定，直到收到 `0x04` |
| 上电后 3 s 未收到任何帧 | 保持 IDLE，不动作 |

## 六、与 ROS2 的对应关系

- `/cmd_vel`（Twist）→ 差速解算 → `v_left / v_right` → `0x01` 帧。
  差速解算公式：`v_L = v - ω·L/2`，`v_R = v + ω·L/2`，`L` 为轮距（mm）。
- `0x10` 帧 → 里程计解算 → 发布 `/odom`（nav_msgs/Odometry）。
  位姿增量：`Δs = (odo_R + odo_L)/2`，`Δθ = (odo_R - odo_L)/L`。
- `state / fault` → 发布到 `/robot_status`（诊断/告警用），C3 侧据此触发报警。

说明：位姿解算放在树莓派侧做，好处是改轮距、轮径不用重刷固件；下位机只保证左右轮里程准确。

## 七、帧示例（已用参考实现验证，可直接作为测试向量）

### 示例 1：设置左右轮各 200 mm/s（上位机 → 下位机）

```
AA 55 06 01 01 C8 00 C8 00 28 B1
```

| 字节 | 含义 |
| --- | --- |
| `AA 55` | 帧头 |
| `06` | LEN = SEQ(1) + CMD(1) + DATA(4) |
| `01` | SEQ = 1 |
| `01` | CMD = 设置轮速 |
| `C8 00` | v_left = 200 mm/s |
| `C8 00` | v_right = 200 mm/s |
| `28 B1` | CRC16-Modbus = 0xB128，小端存放 |

### 示例 2：状态上报（下位机 → 上位机）

```
AA 55 13 02 10 02 00 2E 30 C8 00 C8 00 00 68 0D 00 00 00 00 00 00 F3 EE
```

| 字节 | 含义 |
| --- | --- |
| `AA 55` | 帧头 |
| `13` | LEN = 19 = SEQ(1) + CMD(1) + DATA(17) |
| `02` | SEQ = 2 |
| `10` | CMD = 状态上报 |
| `02` | state = RUN |
| `00` | fault = 正常 |
| `2E 30` | vbus = 12334 mV（12.33V） |
| `C8 00` | v_left = 200 mm/s |
| `C8 00` | v_right = 200 mm/s |
| `00 68 0D 00` | odo_left = 878592 mm |
| `00 00 00 00` | odo_right = 0 mm |
| `00` | cnt = 0（累计里程溢出计数） |
| `F3 EE` | CRC16-Modbus = 0xEEF3，小端存放 |

### 参考实现验证情况

`C1_Keil/Core/Src/protocol.c` 已用 Keil 的 armclang 编译通过（`-Wall -Wextra` 零警告），并用往返测试验证了三种情况：正常帧解析正确、单字节翻转能检出 CRC 错误、帧前有垃圾字节时能自动重新同步。上位机侧实现完后，可直接用上面两串字节做自检。

## 八、实现与测试

- STM32 侧：`Task_Comm` 收帧解析，命令经队列投递给 `Task_Motor` / `Task_Safety`，状态帧由 `Task_Comm` 按 20Hz 组装后用 DMA 发出。
- 电脑端：提供 Python 测试脚本（`tools/serial_tester.py`），可用 USB 转 TTL 直接接 STM32 验证协议，不必等树莓派就绪。
- 上位机侧：给出 ROS2 节点骨架（`tools/ros2_bridge.py` 伪代码级示例），由 C2/C3 的队友补齐串口部分。
