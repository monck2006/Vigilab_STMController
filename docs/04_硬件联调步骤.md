# 硬件联调步骤（第一次上电测试）

固件已经写好，直接烧录即可开始测试。**核心原则：从安全的往危险的来，每一步只加一样东西。**

## 一、需要准备

| 东西 | 说明 |
| --- | --- |
| STM32F407ZGT6 开发板（启明欣欣高配版） | 已烧好或待烧录固件 |
| CMSIS-DAP 仿真器 | 烧录 + 调试，SWD 四线 |
| USB 转 TTL 模块 | **3.3V 电平**那种，用来接串口看数据 |
| 电机驱动板 BTS7960 | 两路 |
| 电机 JGB37-555（带编码器） | 两个 |
| 12V 电源 / 电池 | 给驱动板供电 |
| 杜邦线若干 | |

## 二、接线

### 1. 仿真器（SWD，共 4 根）

```
仿真器 SWDIO  →  开发板 SWDIO
仿真器 SWCLK  →  开发板 SWCLK
仿真器 GND    →  开发板 GND
仿真器 3.3V   →  开发板 3.3V
```

> ⚠️ 调试口必须选 **SWD，不能用 JTAG**——JTAG 的 JTDI/JTDO 正好是 PA15/PB3，被我们用作编码器输入了。Keil 工程里已经配好 SWD。

### 2. USB 转 TTL（接串口，共 3 根）

```
模块 TX  →  开发板 PB11（USART3_RX）
模块 RX  →  开发板 PB10（USART3_TX）
模块 GND →  开发板 GND
```

> ⚠️ TX 和 RX 要交叉接。接反了收不到数据（这是最常见的坑）。
> 波特率 **115200，8N1**。

### 3. 电机与驱动（**第一轮先不接**）

| 开发板 | BTS7960 |
| --- | --- |
| PB4 | 电机1 RPWM |
| PB5 | 电机1 LPWM |
| PB0 | 电机2 RPWM |
| PB1 | 电机2 LPWM |
| PA5 | 电机1 EN（可选） |
| PF11 | 电机2 EN（可选） |
| GND | 驱动板 GND（**必须共地**） |

| BTS7960 | 电机 |
| --- | --- |
| M+ / M− | 电机两根粗线 |
| B+ / B− | 12V 电源 |

### 4. 编码器（接开发板排针）

| 编码器 | 开发板 |
| --- | --- |
| 电机1 A / B | PA15 / PB3 |
| 电机2 A / B | PC6 / PC7 |
| 编码器 5V / GND | 开发板 5V / GND |

> ⚠️ 编码器 A/B 是 5V 电平，我们选的这几个脚都是 **5V 容忍**的（FT），可以直接接。

## 四、测试步骤（按顺序来）

### 第 1 步：只给板子供电，**不接电机**

打开串口工具：

```bash
python tools/serial_tester.py -p COM3 monitor
```

**预期现象**：每 50ms 收到一帧状态，大约这样：

```
[状态上报] 状态=IDLE  故障=正常   电压=12.30V 左轮=    0mm/s 右轮=    0mm/s 左里程=       0mm 右里程=       0mm
```

- 状态应该是 `IDLE`，轮速和里程都是 0
- **没有输出** → 检查 TX/RX 有没有接反、波特率是不是 115200、有没有共地
- **输出乱码** → 波特率不对

### 第 2 步：手转轮子，看里程

用手慢慢转右轮，看"右里程"数字有没有变化，往前进方向转应该是**增加**。

- **数字不变** → 编码器没接好，或 A/B 接反了（接反只会方向相反，不会不变）
- **数字乱跳** → 接触不良
- **方向相反** → 把该轮 A/B 两根线对调

### 第 3 步：接上电机电源（**先把车垫起来让轮子悬空**）

```bash
python tools/serial_tester.py -p COM3 speed 100 100
```

**预期现象**：两个轮子**缓慢地同向转动**（有软启动，不是一下窜出去），状态帧里"左轮/右轮"速度逐渐升到 100mm/s 左右。

- **两个轮子转向相反** → 其中一个电机的两根粗线对调
- **完全不动** → 看状态帧里 `flags` 的 bit0 是不是 1（电源有没有合闸）；也可能是 EN 没接、驱动板没供电
- **一个转一个不转** → 检查那一路的 PWM 线和驱动板接线

### 第 4 步：急停测试

```bash
python tools/serial_tester.py -p COM3 estop
```

**预期现象**：电机**立即停住**，状态变成 `FAULT`，故障码显示"急停锁定"。再发速度指令不会有反应。

恢复：

```bash
python tools/serial_tester.py -p COM3 clear     # 先清急停（要等轮子停稳）
python tools/serial_tester.py -p COM3 speed 100 100   # 再重新发速度
```

### 第 5 步：落地跑，标定里程

```bash
python tools/encoder_calib.py -p COM3 --distance 2000
```

按提示让车走 2 米，然后输入实际距离，脚本会算出修正系数，并告出编码器到底是 11 线还是 13 线。

## 五、常见问题排查

| 现象 | 可能原因 |
| --- | --- |
| 串口完全没输出 | TX/RX 接反、没共地、波特率不对、固件没跑起来 |
| 状态帧一直是 `IDLE`，发速度也不动 | 电源没合闸（flags bit0=0）：查 PA0 那路电源开关接线 |
| 电机不转但状态帧显示在 RUN | 电机驱动没供电、EN 没接、PWM 接线错 |
| 轮子转但里程不变 | 编码器没接、编码器没供电 |
| 里程方向反了 | 该轮编码器 A/B 对调 |
| 一上电电机就转 | **不正常，立即断电**，检查 BTS7960 接线和 EN |
| 烧录失败 | 调试口选成 JTAG 了，改成 SWD；或板子没供电 |

## 六、需要记录的数据

测试时建议记下这几项，后面调参要用：

1. 手转一圈轮子，里程变化多少 mm（理论值 **565.5 mm**）
2. 发 `speed 200 200` 时，状态帧里实际速度是多少
3. 两个轮子空载最高能跑多少 mm/s
4. 急停时电机是立即停还是滑行一段
