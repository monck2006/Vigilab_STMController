# C1 硬件联调步骤

按“先看逻辑、再测传感器、最后驱动电机”的顺序逐步接线。当前源码已重写，但尚未在实际开发板上编译、烧录或验证；请先完成源码构建和板级接线复核。

## 1. 准备

| 设备 | 用途 |
| --- | --- |
| STM32F407ZGT6 开发板 | 运行下位机固件 |
| SWD 下载器 | 烧录和调试；选 SWD，不用完整 JTAG |
| USB 转 TTL | 3.3 V TTL 串口；与 STM32 共地 |
| BTS7960、带编码器电机 | 后续输出测试 |
| 限流电源 | 初次电机测试时限制功率 |

## 2. 串口连接

```text
USB-TTL TX  → STM32 PB11 / USART3_RX
USB-TTL RX  → STM32 PB10 / USART3_TX
USB-TTL GND → STM32 GND
```

串口参数为 115200、8N1。USB-TTL 的 TX/RX 要交叉连接；只接共同地和信号线，不要把 5 V TTL 信号接到串口脚。

烧录本次源码重新构建得到的固件后，可先被动观察：

```powershell
python tools\serial_tester.py -p COM3 monitor
```

状态帧应显示 `IDLE`、轮速 0、里程 0；母线电压显示“未知”，这是因为当前没有电压 ADC。旧的 `release/C1.hex` 不能假定包含本次源码。

## 3. 先校准编码器，不接电机动力

确认编码器供电、A/B 输出电平和开发板输入电压兼容。编码器资料写明 5 V 供电，不等于 A/B 必然输出 5 V；接线前核对模块电路和板卡输入要求。

逐个车轮准确手动转一整圈，记录 TIM2/TIM8 对应计数变化，将实测绝对值填入 `config.h` 的 `ENCODER_COUNTS_PER_WHEEL_REV`。当前 `3584` 是 `16 PPR × 4 × 56` 的暂定假设。

手动向前转时，左右轮状态速度应为正。若方向相反，设置对应 `ENCODER_LEFT_SIGN` 或 `ENCODER_RIGHT_SIGN` 为 `-1`。反向手转时计数符号应相反。

## 4. 检查电机输出脚复用

固件使用 TIM3：PB4/PB5 控制一侧电机，PB0/PB1 控制另一侧电机。原理图显示 PB4/PB5 与 W25Q128 连接，PB0/PB1 与触摸屏信号复用；使用 PWM 时不得同时启用这些板载功能。左编码器 PA15/PB3 需使用 SWD 调试；右编码器 PC6/PC7 与 USART6 互斥。

BTS7960 的 RPWM、LPWM、EN、VCC、GND 和电机电源端子按手中模块版本接线图逐项核对。默认固件不驱动 EN 引脚，也不控制外部电源开关：EN 按模块说明接高电平；PA0 保留为开发板 UART4_TX。

## 5. 车轮架空后测试

接电机动力前先固定底盘、架空驱动轮，并准备好可以直接切断电机电源的物理开关。使用限流电源，一次只测试一个电机。

```powershell
python tools\serial_tester.py -p COM3 drive 50 50
```

`drive` 每 100 ms 重发目标，保持通信看门狗有效；按 Ctrl+C 会发送软停。观察车轮方向、反馈速度符号、目标速度斜坡和状态帧。若任一轮方向不对，立即停止，分别检查电机线序和 `MOTOR_LEFT_SIGN` / `MOTOR_RIGHT_SIGN`。不要用 PI 参数去补偿方向接反或编码器比例错误。`speed` 只发送一帧，适合观察通信失联后的软停。

软停：

```powershell
python tools\serial_tester.py -p COM3 stop
```

软件急停：

```powershell
python tools\serial_tester.py -p COM3 estop
```

软件急停会清零 PWM 并锁定固件输出，但不能保证 MCU 卡死时停止电机；验证时要同时准备硬件断电开关。清除锁定前等待轮子停稳：

```powershell
python tools\serial_tester.py -p COM3 clear
```

## 6. 再调整速度环

完成计数、方向和 PWM 输出确认后再调整 `SPEED_PI_KP`、`SPEED_PI_KI_PER_SECOND`。架空单轮低速开始：先把 Ki 设为 0，逐步增加 Kp；稳定后再慢慢增加 Ki。记录目标速度、实测速度、PWM 和电流。出现持续振荡、速度失控或异常电流时立即断电。

## 7. 当前不能依赖的保护

- 电流和电池电压尚未接入 ADC，状态电压为未知；目前没有真实过流或欠压保护。
- 编码器比例未标定前，堵转检测保持关闭。
- 通信超时和 `CMD_ESTOP` 是软件措施，不能替代硬件急停。
- `release/` 中的旧镜像不一定对应当前源码；请使用重新构建的产物。
