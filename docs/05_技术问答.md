# C1 技术问答（按当前源码）

## 一、硬件分工

### Q1：BTS7960 会自己控制电机速度吗？

不会。BTS7960 是 H 桥功率驱动器，把 STM32 的 RPWM/LPWM 控制信号转换成电机功率输出。编码器直接连 STM32，STM32 才负责测速和速度闭环。

```text
树莓派给目标轮速 → STM32 比较目标和编码器实测值 → PI 算 PWM → BTS7960 驱动电机
```

### Q2：编码器在哪读？

左轮由 TIM2（PA15/PB3）读取，右轮由 TIM8（PC6/PC7）读取。当前 Control 任务在速度环周期读取计数增量并换算速度、里程；编码器不经过 BTS7960。

### Q3：16 PPR 是否等于 3584 个计数/轮转？

不一定。用户提供的资料没有说明 16 PPR 是电机轴还是减速箱输出轴。`config.h` 暂按 `16 × 4 × 56 = 3584`，必须手动将每侧车轮准确转一圈测量计数后确认。

## 二、串口协议

### Q4：怎样发送速度命令？

USART3 使用 115200、8N1。帧格式为 `AA 55 | LEN | SEQ | CMD | DATA | CRC16`。命令 `0x01` 的 DATA 是两个小端 `int16`，分别表示左右轮 mm/s。命令表见 [`02_上下位机通信协议.md`](02_上下位机通信协议.md)。

### Q5：状态帧的电压为什么是未知？

固件还没有配置电池电压 ADC，所以状态帧的电压字段写 `0xFFFF`，串口工具显示“未知”。旧版固定写入的 12.3 V 不是实测值，已移除。

### Q6：通信断开时会怎样？

车辆处于 RUN/STOPPING 时，500 ms 没有合法帧会把目标速度斜坡降到 0；1 s 仍未收到新帧就进入锁定故障。若车已处于 IDLE，则不会因为树莓派启动慢而锁定。

## 三、控制和状态

### Q7：这是 PID 吗？控制周期多长？

当前实现是 PI，没有 D 项。TIM7 每 1 ms 唤醒 `Task_Control`；编码器和速度 PI 每经过至少 20 ms 更新一次，目标速度通过斜坡限制变化。PI 按实际经过的秒数更新积分项，并限制输出和积分值。

`config.h` 中的 PI 系数仅是起始值。需要先确认编码器比例和方向，再架空单轮低速调试与整定。

### Q8：软停、急停有什么区别？

- `CMD_STOP`：将目标斜坡降到 0，等待轮速降低后转入 IDLE。
- `CMD_ESTOP`：清零 PWM 并锁定软件输出，轮子停稳后可通过 `CMD_CLEAR_ESTOP` 清除。

软件急停依赖 MCU、定时器和固件仍正常运行，不能替代独立硬件急停或电机电源切断开关。

### Q9：电流、欠压和堵转保护是否已实现？

当前没有电机电流和电池电压 ADC，因此没有真实过流、欠压保护；不能用占空比估算冒充实测电流。编码器静止堵转检测默认关闭，等计数标定并上板检查后再考虑启用。

### Q10：状态帧 flags 的 bit0 是电池供电正常吗？

不是。bit0 表示“软件控制的外部电源开关输出为 ON”；当前默认没有这个控制输出，因此 bit0 为 0，不能据此判断电机电源是否实际接通。bit1 表示固件允许 PWM 输出，bit2 表示软件锁定状态。

## 四、代码和任务

### Q11：为什么把控制放到一个任务？

`Task_Control` 顺序处理速度命令、安全状态、编码器、PI 和 PWM，减少多个任务同时修改同一组轮速/电机状态的机会。`Task_Telemetry` 单独负责串口发送，避免多个任务并发调用 UART 发送接口。

### Q12：外设是什么节奏？

| 部分 | 当前配置 |
| --- | --- |
| TIM3 PWM | 20 kHz |
| TIM7 控制唤醒 | 1 kHz |
| 编码器/速度 PI | 至少每 20 ms（50 Hz） |
| 状态帧 | 每 50 ms（20 Hz） |
| USART3 | 115200、8N1，接收逐字节中断，发送任务轮询 |

### Q13：为什么 PA0 不能直接当急停电源控制？

开发板原理图把 PA0 接作 UART4_TX 引出，没有显示它连接到电机电源开关。当前固件默认不配置 PA0。若要远程切电，需要先接入并验证外部开关电路；物理急停仍应独立可用。
